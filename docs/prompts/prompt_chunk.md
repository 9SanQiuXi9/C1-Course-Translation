# 管线 ③ 切块：可复制 Prompt

> **使用方式**：在新对话中把「主 Prompt」整段复制给 AI。不需要前置上下文。
> **前置条件**：抽取已完成（`extracted/*.md` 已生成）
> **产出**：`chunk.py` → `chunks.jsonl` + 切块自检报告

---

## 主 Prompt（复制这里开始）

```
【项目背景，请先读完再动手】

我在做一个课程资料的翻译项目：把一批英文课程资料翻译成中文，做成别人能复用的资料包。
现在要做管线的第三环：切块（chunking）。

为什么需要切块：
上一步已经把所有原始资料（网页、PDF）统一抽成了 Markdown，
但格式统一 ≠ 大小合适。最大的 .md 文件有约 57,000 字符（约 19,000 英文词），
一次性丢给 AI 翻译会出问题：
  - AI 会悄悄跳过中间部分，而且返回结果看起来是完整的（最危险）
  - 一处翻错就要整篇重来，浪费大量 token
  - 无法并行处理
  - 出错时无法定位到具体位置
所以必须切成小块。

【输入】
  extracted/*.md  上一步抽取产出的标准化 Markdown
  extract_report.json  抽取报告（含每个文件的字符数、代码块数等）

【我的环境限制】
  - 只能用 Python 标准库。装不了第三方库。
  - Windows，控制台 GBK，打印必须用 UTF-8。

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
【架构要求（很重要，请先理解）】
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
chunk.py 里【绝对不要】出现任何 HTML 解析、PDF 解析、zlib 解压的逻辑。
格式差异已经在 extract.py 那一层处理完了。本脚本只负责「按大小切分」。

如果 AI 写了格式解析代码，说明理解错了架构。

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
【输入文件的结构约定（extract.py 已保证）】
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
- 文件开头是 YAML front matter（--- 包裹），字段包括：
  source_file, origin_url, title, extract_method(html/pdf/spa),
  extract_warnings, chars, code_blocks, tables, links
  （pdf 来源额外有 pdf_type, readable_line_ratio）
- 全文恰好一个 "# "（H1）= 文章标题
- 章节标题是 "## " 和 "### "
- 代码块被 <!-- CODE_BLOCK_START id=cN lang=xxx --> 和
  <!-- CODE_BLOCK_END id=cN --> 两行注释包裹
- 表格是 Markdown 管道表格，复杂表格可能是原始 <table> HTML

⚠️ 不要把文件名硬编码在脚本里。应该扫描 extracted/ 目录，
   这样换一门课只改顶部路径常量，符合可复用要求。

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
【切分规则】
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
1. 切点只认 "## " 和 "### " 两种标题。
   "# "（H1，文章标题）不产生切块，只作为该文件所有块的 doc_title。
   front matter 的内容不进入任何块。

2. 切点放在标题那一行的前面，标题跟着它下面的内容走。
   标题不能单独成为一块，也不能留在上一块的末尾。

3. 保护规则（绝对不许切断）：
   - CODE_BLOCK_START / CODE_BLOCK_END 之间的内容 ⇒ 必须完整在同一块
   - Markdown 表格（连续的 | 开头行，含分隔行 |---|）⇒ 必须完整在同一块
   - 列表（连续的 - / * / 1. 开头行）⇒ 尽量完整，必要时整体移入下一块
   - 引用块（> 开头）⇒ 尽量完整
   如果某个代码块本身超过 8000 字符，允许它单独成一块。

4. 块大小调整（在遵守第 3 步保护规则的前提下）：
   - < 500 字符：与相邻块合并（若它是唯一块则保留）
   - 500 ~ 8000 字符：保留
   - > 8000 字符：在「段落边界」（空行分隔处）再切一刀
     ⚠️ 再切时依然不许切断代码块/表格/列表

5. 无标题文件的处理（⚠️ PDF/SPA 来源常见）：
   如果某个 .md 完全没有 "## " 或 "### "（例如 OCR 出来的 PDF 没有标题结构）：
   a) 按「空行分隔的段落」切成 2000-4000 字符的块
   b) 在报告里单列一类 no_heading_files，列出这些文件及其字数
   c) ⚠️ 不要因为没标题就整篇作为一块（那等于没切）
   d) ⚠️ 也不要把块切在句子中间：切点必须落在段落边界

6. 如果某个 .md 不存在（抽取失败），跳过并在报告里记录，不要凭空造块。

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
【每块的元数据字段】
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
chunk_id       唯一编号，格式 "<md文件名去掉.md>#<三位序号>"，如 mcp-introduction#001
source_file    来源 md 文件名
origin_url     从 front matter 继承
doc_title      从 front matter 的 title 继承
extract_method 从 front matter 继承（html/pdf/spa）—— 便于后续区分质量
heading_path   该块所属标题路径数组，如 ["## MCP 架构", "### 服务端"]
               若该块在第一个章节之前，或该文件无标题结构，则为 []
index          该块在本文中的序号，从 1 开始
total          该文件一共切出多少块
chars          该块正文字符数
has_code       是否含代码块（布尔）
code_block_ids 该块包含的代码块 id 数组，如 ["c3","c4"]
text           该块的正文内容（含标题行本身）

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
【输出 chunks.jsonl】
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
每行一个 JSON 对象，【不是】一个大 JSON 数组。
理由：好追加（翻一块写一块）、一块坏了不影响其他块、便于流式处理。

字段顺序：chunk_id, source_file, origin_url, doc_title, extract_method,
        heading_path, index, total, chars, has_code, code_block_ids, text

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
【控制台自检（必须打印）】
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
1. 总量核对：所有块的 chars 之和，对比各文件 front matter 里 chars 字段之和，
   打印两个数值和误差百分比。误差 > 1% 时列出差异最大的 5 个文件。
2. 块数统计：总块数、每个文件的块数。
3. 超小块检查：列出所有 chars < 200 的块。
4. 重复检查：有没有两块的 text 完全相同（跨文件也算），列出重复的 chunk_id。
5. 边界抽查：随机抽 5 个块，打印前 80 字符，确认开头是标题行或完整句子，
   而不是半句话。
6. 代码块完整性：
   - 统计所有块里 CODE_BLOCK_START 出现次数，与各文件 front matter 里
     code_blocks 字段之和对比
   - 检查每个 CODE_BLOCK_START id=cN 是否都有配对的 CODE_BLOCK_END id=cN
7. 跨块重复检测：检查有没有连续两块的 text 尾部/头部有超过 200 字符的重叠。
   （这是「跨块多译」bug 的预防检查，很重要）

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
【按来源分组的报告】
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
因为 html / pdf / spa 三种来源的文本质量不同，请【按 extract_method 分组】
统计：每组的文件数、块数、总字符数、无标题结构的文件数。
这样能一眼看出 PDF 来源的块是否质量异常。

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
【约束】
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
- 只用 Python 标准库
- 输入目录、输出路径写成文件顶部常量（换课程只改这几行）
- 关键步骤写中文注释
- 幂等：重复运行产出完全相同
- 控制台打印用 UTF-8

请直接给出完整的 chunk.py 代码。
```

## 常用调试 Prompt

```
运行 chunk.py 出问题了：

【我的操作】
python chunk.py

【报错信息 / 异常结果】
（整段贴原文，不要改写）

【我观察到的问题】
（例：某个 OCR 出来的 PDF 没有任何 ## 标题，被整篇当成 1 块）

【我认为可能的原因】
（例：OCR 文本没有标题结构，触发了规则 5 的降级分支）

请定位原因并修复，说明改了什么。
```

| 症状 | 大概率原因 | 该说什么 |
|---|---|---|
| PDF 来源整篇成 1 块 | 无标题降级逻辑没生效 | "请实现规则 5a：无标题时按段落边界切成 2000-4000 字符" |
| 某文件只切出 1 块 | 该文件没有 `##` 级标题 | "请打印每个文件的 ## 和 ### 数量，找出为 0 的文件" |
| 总量误差 > 1% | 切分时漏了段落 | "请定位差异最大的文件，打印它切分前后的字符数" |
| 代码块被切断 | 保护逻辑失效 | "请检查是否有块以 ``` 结尾但没有对应的开头" |
| START/END 不配对 | 切分点落在代码块内部 | "请检查所有 CODE_BLOCK_START 是否都有配对的 END" |
| 出现超小块 | 切点连续 | "请把 < 500 字符的块与相邻块合并，注意别破坏代码块保护" |
| 连续块有重叠 | 上下文重叠逻辑过头 | "请检查第 7 项自检，列出重叠超过 200 字符的块对" |
| 块数过多 | 切得过细 | "块数偏多，请把 < 1000 字符的相邻块合并" |
| **脚本里有 zlib / HTML 解析** | **架构理解错了** | "chunk.py 不应有任何格式解析逻辑，请移除" |

## ⚠️ 四个必须理解的检查项

| 检查项 | 防什么故障 | 不做的后果 |
|---|---|---|
| **总量核对**（自检 1） | 内容丢失 | 有段落没被任何块接住，永久漏译 |
| **代码块 START/END 配对**（自检 6） | 切点落进代码块 | 翻译时把半段代码当正文翻 |
| **跨块重叠检测**（自检 7） | **跨块多译** | 拼回后出现重复段落（真实踩过的坑） |
| **无标题结构统计**（规则 5b） | PDF 来源被默默退化 | 整篇当 1 块，**看起来成功了，实际等于没切** |

---

## 验收标准

| 项 | 标准 | 不合格怎么办 |
|---|---|---|
| 总块数 | **200–400 块** | 偏少→标题没识别出；偏多→切太细 |
| 单块大小 | 多数 2000–4000 字符 | 调整合并阈值 |
| 总量误差 | **< 1%** | 找差异最大的文件逐个查 |
| 超小块（< 200 字符） | **0 个** | 合并逻辑没生效 |
| 重复块 | **0 个** | 切分逻辑有 bug |
| 代码块总数一致 | **完全一致** | 代码块保护失效 |
| START/END 配对 | **100% 配对** | 切点落在代码块内 |
| 跨块重叠 > 200 字符 | **0 对** | 检查重叠逻辑 |
| 无标题结构的文件 | **报告里已单列** | 降级逻辑没实现 |
| 脚本内无格式解析代码 | **确认没有** | 架构理解错了，要求重写 |

## 完成后立刻做的三件事

1. **把自检报告存进 `logs/chunk_report.txt`** —— 这是 README 里「块级校验」的证据
2. **导出这次 Session 日志**存进 `logs/`
3. **把总块数写进 `stats.json`**，后面术语槽位校验和完整性校验都要引用它
