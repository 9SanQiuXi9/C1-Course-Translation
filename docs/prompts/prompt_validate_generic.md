# 质量校验脚本：通用生成提示词

> **用途**：为「英文原文 + 中文译文」的翻译项目生成质量校验脚本。
> **通用性**：不绑定任何具体项目。只改顶部路径常量即可用于别的翻译任务。
> **用法**：整段复制到新对话。

---

## 主 Prompt

```
【任务】
写一个 Python 脚本，用于校验一个翻译项目的质量。
项目形态：一批英文原文文件，对应一批中文译文文件。
目的是【证明】译文质量，而不只是"抽看几段"，所以每层校验都要产出可核对的数字。

【脚本名】check_quality.py

【环境约束】
  - 只用 Python 标准库（re, json, os, math, random, hashlib, collections, difflib）
  - 运行环境 Windows，控制台是 GBK 编码，脚本开头必须：
      try: sys.stdout.reconfigure(encoding="utf-8")
      except Exception: pass
  - 脚本无法调用任何大模型 API（无密钥无额度）。

【路径约定】
  所有输入输出路径写成文件顶部常量，便于换项目时只改这几处，例如：
    SRC_DIR    = "..."   # 英文原文目录（*.md）
    DST_DIR    = "..."   # 中文译文目录（*.md）
    GLOSSARY   = "..."   # 术语表 JSON（可选，没有则跳过术语层）
    OUT_DIR    = "..."   # 报告输出目录

【原文与译文的文件格式】
  两种格式都要支持，自动判断：
    A) 带 YAML front matter 的 Markdown（--- 包裹的元数据 + 正文）
    B) 纯 Markdown 或纯文本
  译文文件名与原文同名，便于配对。
  译文目录里可能混有非译文文件（如 *.PROMPT.md 这类留痕文件），需要排除。

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
【子命令】
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  check_quality.py all        跑全部自动层
  check_quality.py l1         结构完整性
  check_quality.py l2         术语一致性
  check_quality.py l3         校验器反例自测
  check_quality.py l4-sample  生成语义标注任务（供人工标注）
  check_quality.py l4-score   汇总人工标注，计算一致性统计

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
【L1 结构完整性】
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
1. 先确定范围：原文 N 篇；配对上译文的 M 篇；列出「未翻译」和「多余译文」
   ⚠️ 未翻译不算失败，单独列出即可。

2. 逐篇比对 7 项（只比对已翻译的）：
   a) Markdown 标题行数（^#{1,6}\s）
   b) 围栏代码块数量（``` 成对计数）
   c) 代码块内容【逐字节一致】
      ⚠️ 比较前先归一化换行符（\r\n → \n）和行尾空白，避免误报
   d) 表格行数（以 | 开头的行）
   e) 链接数量（https?:// 出现次数）
   f) 正文非空行数
   g) 长度比 = 译文非空白字符数 / 原文非空白字符数
      （英译中通常 0.4–0.8 属正常；< 0.3 判为疑似漏译）

3. 统计口径：逐项给出「达标篇数 / 已比对篇数」，如 "code_blocks_ok": "24/24"
   ⚠️ 任何一项不达标，必须列出具体是哪几篇。
   ⚠️ 长文档段首段尾各比对一次，避免"中间整段跳译"被长度比掩盖。

【输出】L1 报告 JSON
{
  "scope": {"src_docs": N, "translated": N, "not_translated": [...], "extra": [...]},
  "per_doc": [{"doc":"...", "title_lines":{"src":8,"dst":8,"ok":true},
               "code_blocks":{"src":3,"dst":3,"ok":true,"bytes_identical":true},
               "table_lines":{...}, "links":{...},
               "length_ratio":0.62, "status":"ok"}],
  "totals": {"title_lines_ok":"24/24", "code_blocks_ok":"24/24",
             "tables_ok":"...", "links_ok":"...",
             "length_ratio_median":0.62, "length_ratio_outliers":[...]}
}

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
【L2 术语一致性】
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
前提：有一个术语表 JSON。格式约定：
{
  "frozen_hash": "...",
  "terms": [
    {"en": "agent", "zh": "智能体", "handling": "translate",
     "case_sensitive": false, "note": "..."}
  ]
}
handling 取值及判据【必须分开实现，不要混用】：
  "translate"  术语必须译成中文
               → 检查译文对应位置是否出现指定的中文译法
               ⚠️ 判据要宽松：同一英文词在译文里可能有多种中文形式，
                  只要该处出现了指定译法即算命中。
  "keep_en"    术语保留英文
               → 检查译文里该英文词是否仍然存在；若被译成中文算未命中
  "acronym"    同 keep_en
  "bilingual"  首次双语、之后中文
               → 只检查是否用了指定中文译法，不强制检查双语格式

配对方式：按段落配对。把原文与译文都按空行切成段落，
          原文段落 i 对应译文段落 i。段落数不一致时取较小的那一边，
          并把段落数差异记进警告。

■ 关键：统计槽位前必须过滤「非正文行」
  网页抽取出来的原文常残留导航、页脚、链接列表，会污染槽位统计。
  实现一个过滤函数，判定为非正文行的规则：
    def is_content_line(line):
        urls = len(re.findall(r"https?://", line))
        if urls == 0: return True
        if re.match(r"^\s*!\[", line): return False              # 纯图片
        if re.match(r"^\s*[-*]?\s*A?\s*https?://", line): return False  # 导航项
        if urls >= 2: return False
        if len(line.strip()) < 120: return False                 # 短行+含链接
        return True
  打印「排除行数 / 总行数」供核对。

■ 必须区分两种未命中
  - 该文档长度比 < 0.3  → 判为【疑似漏译】，其未命中【不计入】术语命中率
  - 否则                → 判为【译法不一致】
  理由：整段漏译会让该文档所有槽位失效，混进命中率会让数字失去意义。

■ 冻结校验
  读术语表的 frozen_hash；重新计算当前术语表内容的哈希（排除 frozen_hash 字段
  自身，否则循环依赖）。两者不一致 → 报错退出，提示"术语表已改动，请重跑校验"。
  理由：术语表可随时改，则"高命中率"无意义。

【输出】L2 报告 JSON
{
  "glossary_hash": "...",
  "docs_compared": N,
  "slots_total": 931, "slots_hit": 884, "hit_rate": 0.9495,
  "by_handling": {
    "translate": {"slots": 600, "hit": 570, "hit_rate": 0.95},
    "keep_en":   {"slots": 331, "hit": 314, "hit_rate": 0.9486}
  },
  "suspected_omissions": [{"doc":"...", "length_ratio":0.21}],
  "per_term": [{"en":"agent","zh":"智能体","slots":291,"hits":289,
                "misses":[{"doc":"...","snippet":"..."}]}],
  "per_doc":  [{"doc":"...","slots":42,"hits":42}]
}

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
【L3 反例自测】⚠️ 必须实现，否则 L1/L2 的数字不可信
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
一个失效的校验器比没有校验更危险 —— 它会给出虚假的信心。

做法：在内存里构造"被破坏的"样本，断言校验器必须报警。
至少覆盖这 8 种情形：
  1. 代码块被翻译了        5. 术语用了错误译法
  2. 代码块被删除了        6. 整段漏译（长度比 < 0.3）
  3. URL 被改写            7. 表格行被合并
  4. 标题行被删            8. 译文为空

要求：
  - 每个反例的期望结果是"必须被检出"
  - 任何一项没被检出 → all_pass = false，退出码非 0，明确指出哪一项失效
  - ⚠️ 不要写永远通过的假自测。设计时先自问：
      "如果我故意写错，这段逻辑真的会报错吗？"

【输出】{"cases_total":8, "cases_detected":8, "all_pass":true,
        "cases":[{"name":"代码块被翻译","detected":true}]}

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
【L4 语义质量】
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
脚本无法调用大模型，所以语义判定由人工在对话里完成。
脚本只负责：分层抽样 → 生成标注任务 → 汇总两份标注 → 计算统计量。

■ l4-sample：分层抽样
  不要随机抽。按风险分层，目标 10–12 个文档 × 每篇 5 个自然段 = 50–60 个判定点：
    层1：字符数最长的 3 篇各抽 1 段
    层2：代码块最多的 3 篇各抽 1 段
    层3：表格最多的 3 篇各抽 1 段
    层4：术语密度最高的 3 篇各抽 1 段
    层5：文本质量可能受损的文档抽 2 段
        （判据可由调用方指定：文件名特征、或 front matter 里的质量字段）
  ⚠️ 只从【已翻译】的文档里抽。
  每段从文档中部取 5 个自然段，跳过代码块、表格、以及非正文行。
  用固定随机种子（写在常量里）保证可复现。

  生成两份标注任务 annotator_A.md 与 annotator_B.md，每份含：
    段落原文 + 对应译文 + 判定标准
  ⚠️ 关键：标注任务里【不要给术语表】！
     否则标注者只是在复述既有口径，等于自己批改自己，一致性会虚高。
  ⚠️ 两份内容相同，但要求在不同对话/不同时间独立完成。

  同时生成空的 annotator_A.json / annotator_B.json 模板供填写，每个判定点：
    {"doc":"...","para":3,"omission":"yes|no","mistranslation":"yes|no",
     "term_drift":"yes|no","machine_tone":"yes|no","overall":"PASS|FAIL"}

■ l4-score：汇总统计
  a) 观察一致率  Po = 两人 overall 判定相同的比例
  b) Cohen's κ：
       Pe = P(A=PASS)·P(B=PASS) + P(A=FAIL)·P(B=FAIL)
       κ = (Po - Pe) / (1 - Pe)
       Landis & Koch 解释区间：
         <0 差 | 0–0.20 轻微 | 0.21–0.40 一般 | 0.41–0.60 中等
         0.61–0.80 显著 | 0.81–1.00 几乎完全一致
     ⚠️ 用 κ 而非简单一致率：若绝大多数判定点都是 PASS，
        两人即使随机判也有一致率，κ 会扣掉"碰巧一致"的部分。
  c) 每个缺陷维度的检出率 + 95% Wilson 置信区间：
       p̂ = k/n
       中心 = (p̂ + z²/(2n)) / (1 + z²/n)
       半宽 = z·sqrt(p̂(1-p̂)/n + z²/(4n²)) / (1 + z²/n)
       区间 = [中心 − 半宽, 中心 + 半宽]，z = 1.96
     ⚠️ 必须用 Wilson，不能用正态近似。
        因为报"检出 0 个漏译"时，正态近似会给出零宽度区间（统计上荒谬）；
        Wilson 会给出 [0, 0.065] 这类合理区间，意思是"很可能低于 6.5%"。
  d) 分歧清单：列出两人判定不同的判定点，供人工裁定

【输出】L4 报告 JSON
{"sample_size":55,
 "agreement":{"observed_agreement":0.93,"expected_agreement":0.58,
              "cohen_kappa":0.83,
              "interpretation":"几乎完全一致 (Landis & Koch 0.81-1.00)"},
 "defect_rates":{
   "omission":{"k":2,"n":55,"rate":0.036,"wilson_95":[0.010,0.122]},
   "mistranslation":{"k":3,"n":55,"rate":0.055,"wilson_95":[0.019,0.146]},
   "term_drift":{"k":1,"n":55,"rate":0.018,"wilson_95":[0.003,0.095]},
   "machine_tone":{"k":4,"n":55,"rate":0.073,"wilson_95":[0.029,0.171]}},
 "disagreements":[{"doc":"...","para":3,"A":"PASS","B":"FAIL"}]}

【汇总 stats.json（供 README 引用）】
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
【控制台输出要求】
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
1. 范围：已译 N 篇 / 未译 N 篇（列出未译的）
2. L1 逐项：达标篇数 / 已比对篇数；不达标的列出文档名

4. L3：反例自测结果，未检出的明确指出
5. L4：抽样规模；未完成则提示下一步
6. 最终 headline 数字

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
【其他要求】
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
- 只读输入，绝不修改任何原文或译文
- 幂等：同一输入重复运行结果完全相同
- 退出码：全部通过 0；L1/L2/L3 有失败项或自测未通过返回非 0
- 关键步骤写中文注释

请先给出设计方案（各函数职责、报告结构、文件组织），我确认后再给完整代码。
```

## 出问题时怎么问

```
运行 check_quality.py 出问题了：

【我的操作】
python check_quality.py l2

【报错信息 / 异常结果】
（整段贴原文，不要改写）

【我观察到的问题】
（例：术语命中率只有 60%，但我确实按术语表译的）

【我认为可能的原因】
（例：keep_en 类术语的判据可能写错了——该查英文是否保留，却去查了中文）
```

| 症状 | 大概率原因 |
|---|---|
| 命中率异常低 | `keep_en` / `acronym` 类的判据写错（应查英文是否保留，而非查中文） |
| 命中率异常高（>99%）且样本很少 | 校验逻辑没真正执行 —— 检查 L3 自测是否也全过 |
| 代码块校验误报不一致 | 比较前没做换行符/行尾空白归一化 |
| 疑似漏译列表里全是正常文档 | 长度比阈值太严（英译中 0.4–0.8 正常） |
| L1 报"多余译文" | 把留痕文件（如 `.PROMPT.md`）误当译文 |
| 自测永远通过 | 自测是假的 —— 要求构造必然失败的样本 |
| Wilson 区间宽度为 0 | 用了正态近似，应改用 Wilson 公式 |
| L4 抽到未翻译的文档 | 抽样范围没限定在已翻译集合 |

## 验收标准

| 层 | 项 | 标准 |
|---|---|---|
| L1 | 范围 | 明确区分已译/未译，未译不算失败 |
| L1 | 代码块逐字节一致 | 100% |
| L2 | handling 分类 | **三类判据分开实现**，不混用 |
| L2 | 非正文行过滤 | 已实现，并打印排除比例 |
| L2 | 疑似漏译 | **单独归类**，不混进命中率 |
| L2 | 冻结校验 | 哈希不一致即报错退出 |
| L3 | 反例自测 | **全部检出，且能真正失败** |
| L4 | 标注独立性 | 标注任务**不含术语表** |
| L4 | κ 与 Wilson | 均已实现，且给区间解释 |
| 汇总 | `stats.json` | 无手填常量 |
| 安全 | 输入只读 | 确认未修改任何原文/译文 |
