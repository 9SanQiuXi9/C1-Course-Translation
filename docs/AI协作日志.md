### 2.2 一个值得记下来的工作方式：用临时脚本代替手改

本次几乎所有批量修改都**没有直接手改**，而是先写一个临时脚本执行。理由在本次被反复验证：

- **可复现**：修改逻辑写下来，能重跑、能审阅
- **有断言**：脚本里 `assert old in t`，锚点找不到就中止，**不会静默改错**
- **能自证**：脚本末尾往往带「复查」段，改完立刻验证

```python
# 典型形态（本次用了十几次）
old = '''...精确原文...'''
new = '''...替换内容...'''
assert old in t, "handle_plain 未找到"      # ← 关键：锚点不存在就停
t = t.replace(old, new, 1)
open(p, "w", encoding="utf-8", newline="").write(t)
# 复查：确认全文再无「只看 status 就落盘」的写法
```

**并用**：这类脚本用完即删，不留残留（本次结束前逐个清理过）。

## 4. 踩坑记录

### 4.1 最有价值的一类坑：**校验器自己失效**

本项目的核心风险不是「译错」，而是「**校验器看起来通过了，其实什么都没检**」。
本次抓到 3 个这类坑，是全日志最有价值的部分。

---

#### 坑 1｜表格容差过宽：合并 1 行被判为达标

- **症状**：L3 反例自测中「表格行被合并」用例**未检出**
- **根因**：表格用了通用容差 `within_tolerance(st, dt)`（默认允许 ±1 行），
  而表格是多行结构，少 1 行就是结构损坏
- **修复**：表格单独给 0 容差

```python
# check_quality.py
TABLES_MAX_REL_DIFF = 0.0
TABLES_MIN_ABS_SLACK = 0
```

- **发现方式**：L3 反例自测（只有自测能发现「判定太松」）
- **教训**：容差要按**结构类型**分别设定，不能一套通用值打天下

---

#### 坑 2｜★★★ 自测与生产走两条不同路径 → 假自测

- **症状**：修完坑 1 后，自测**仍然报「未检出」**
- **根因**：L3 自测直接调用 `within_tolerance(st, dt)`（走默认容差），
  而 L1 生产路径调用的是 `within_tolerance(st, dt, 0.0, 0)`。
  **两条路径参数不同**，所以「改生产容差」对自测毫无影响 ——
  自测检的是另一套逻辑，永远检不出问题

  ```python
  # 生产路径（L1）
  if _l1_fails(...):          # 内部走 check_l1_doc → 0 容差
  # 自测路径（改之前）
  detected = not within_tolerance(st, dt)   # ← 走默认容差，与生产无关
  ```

- **修复**：8 个反例全部改为调用 `_l1_fails()` → `check_l1_doc()`，**即生产路径本体**
- **发现方式**：坑 1 修完仍失败 → 逼我去看自测到底调了什么
- **教训**：**自测必须走生产代码路径**。自测若自己重写一份判定逻辑，
  它验证的是那份副本，不是真校验器 —— 这是最危险的一类「虚假信心」

> 这个坑的价值在于：如果没有坑 1，坑 2 可能永远发现不了。
> 因为自测会一直「全部通过」，看起来完美。

---

#### 坑 3｜空标注模板算出假一致性 κ=0.0

- **症状**：L4 空跑（两份标注模板都没填）时输出 `Po = 1.0`、`κ = 0.0`，
  看起来像「两位标注者完全不一致」
- **根因**：两份模板的 `overall` 字段都是**空字符串**，归一化后**相等**，
  于是被当成「两人判定一致」
- **修复**：排除未填写与 `SKIP` 的判定点，并如实报告已填写数量

```python
VALID = {"PASS", "FAIL", "SKIP"}
scored = [k for k in keys
          if norm(da[k].get("overall")) in VALID
          and norm(db[k].get("overall")) in VALID
          and norm(da[k].get("overall")) != "SKIP"
          and norm(db[k].get("overall")) != "SKIP"]
if not scored:
    print("ℹ️ L4 待人工完成：两份标注的 overall 都还是空的")
    return None
```

- **发现方式**：L4 空跑时输出的 κ=0.0 不合常理 —— 两份空白模板不可能有「一致性」
- **教训**：统计量在**样本为空**时要显式判断，不能让它算出数来。
  空集上的任何「比率/一致性」都是无意义的

#### 坑 4｜L2 段落严格索引配对 → 命中率 47.59%

- **症状**：L2 术语命中率只有 **47.59%**，而 `check_slots.py --verify` 的全篇口径是 ~95%
- **根因**：按段落索引一一对应配对。中英段落切分习惯不同，
  加上网页抽取常留重复块，索引会**逐段累积错位**。实测查到原文第 53 段讲 agent、
  译文第 53 段讲新闻列表 —— 完全对不上
- **修复**：加 ±3 段落窗口（`PARA_WINDOW = 3`），命中率升至 81.77%
- **发现方式**：数字异常低 + 抽查具体段落
- **教训**：跨语言比对**不能假设段落一一对应**

---

#### 坑 5｜L4 抽样两侧索引空间不同 → 判定点完全错位

- **症状**：抽样生成的判定点里，「原文讲图像生成」对应「译文讲成为世界级提示词工程师的技巧」
- **根因**：`pick_paragraphs` 对原文按 0.15 裁剪后再取样，
  但译文却从索引 0 取值。**两个不同的索引空间**
- **第一次修复**：两侧统一用同一索引空间 + 加 `para_similarity` 自检
- **第二次修复（更彻底）**：改用**章节锚点对齐** + **跨语言共享键**校验
- **关键认识**：`difflib` 字符相似度**无法区分「段落错位」和「语言不同」** ——
  中英字符集不同，相似度天然接近 0，所以它是**无效信号**

  真正的对齐信号是**跨语言逐字保留的内容**：

  ```python
  def cross_lingual_keys(text):
      """URL / 代码标识符 / 数字 / 专名 —— 这些在翻译里逐字保留，
         是唯一可靠的中英对齐锚点。"""
  ```

- **发现方式**：人工核对判定点 1、2 的内容是否对应
- **教训**：**度量指标要能区分两种不同的失败原因**，否则它只是噪声

#### 坑 6｜L2 未命中不分原因 → 81.77% 会被误读

- **症状**：L2 命中率 81.77%，看起来「术语一致性很差」
- **根因**：未命中的 621 处里，**530 处是段落配对偏移**（术语在全篇存在，只是没配到那段），
  只有 91 处是「全篇都没用指定译法」的真漂移
- **修复**：加 `doc_level_present` 判定，把未命中分成两类呈现

  ```
  未命中 621 处，分两类：
    · 配对偏移（译法在全篇存在，非术语问题）  530
    · 确凿漂移（全篇未用指定译法，真问题）    91   占槽位 2.29%
  ```

- **发现方式**：81.77% 与 `check_slots.py --verify` 的 ~95% 差距过大 → 追查差距来源
- **教训**：一个「不好看」的数字，可能只是**度量方式的问题**。
  不做归因分析就下结论，会把工具误差当成质量问题

#### 坑 7｜L4 采样把广告文案也采进来了

- **症状**：判定点原文是 `Get started for free`（网页按钮），译文是 `试用聊天提示词`
- **根因**：网页残留的 CTA 广告文案很短，被当成正常段落
- **修复**：按长度过滤（英文 ≥80 字符、中文 ≥30 字符）
- **发现方式**：人工核对判定点内容
- **教训**：抽取残留要**在采样前**过滤，否则会污染人工标注

### 4.3 工程类坑

---

#### 坑 8｜单层子命令退出码恒为 0

- **症状**：`check_quality.py l1` 明明报了「标题行数 0/1 ❌」，退出码却是 **0**
- **根因**：退出码只在 `all` 分支里计算，单层分支一律 `return 0`
- **危害**：CI 会误判为通过
- **修复**：`exit_code()` 改为可选参数，所有分支都返回对应退出码

  ```
  验证（沙箱注入破坏）：
    l1（标题数 3 vs 1）  exit=1  ✅
    l2（冻结哈希被改）   exit=2  ✅
    all                 exit=1  ✅
  ```

- **发现方式**：写了个沙箱测试**专门验证「非零退出码真的会非零」** ——
  这个测试本身的设计就是关键：不测「通过时返回 0」，而测「失败时返回非零」
- **教训**：退出码必须**用注入失败的方式验证**。只看成功路径等于没测
- **副产物**：这次沙箱测试用的是**改常量的脚本副本**，不污染真实项目

---

#### 坑 9｜写盘前不建父目录（5 处）

- **症状**：换源到新目录时 `FileNotFoundError: .../work/reports/manifest.json`
- **根因**：`open(path, "w")` 前没有 `os.makedirs(os.path.dirname(path))`。
  **真实项目里这些目录早已存在**，所以这个缺陷藏了很久，只有换源才暴露
- **涉及**：`build_manifest.py` `OUT_PATH` · `extract.py` `EXTRACT_REPORT_PATH`
  `MANIFEST_PATH` · `init_glossary.py` `GLOSSARY_PATH` · `check_slots.py` `SLOT_REPORT_PATH`
- **修复**：全部补上，并写了个**全文扫描脚本**复查「所有写盘点是否都有父目录保障」
- **发现方式**：端到端换源测试
- **教训**：在「当前环境恰好满足」的前提下，缺陷不会暴露。
  **换一个环境跑一遍**是最有效的检查手段

---

#### 坑 10｜★★ 默认参数绑定路径常量 → `configure()` 之后失效

- **症状**：换源参数「生效了」，但文件仍写在老地方
- **根因**：Python 的**默认参数在函数定义时求值一次**：

  ```python
  # ❌ import 时就绑死了 GLOSSARY_MD_PATH 的旧值
  def write_glossary_md(gloss, path=GLOSSARY_MD_PATH):
      ...
  ```

  之后 `configure()` 改全局变量，**这个默认值不会跟着变**
- **修复**：默认值改 `None`，函数体内实时读取

  ```python
  def write_glossary_md(gloss, path=None):
      if path is None:
          path = GLOSSARY_MD_PATH      # ← 实时读取
  ```

- **同类**：`check_slots.py` 的 `load_glossary(path=GLOSSARY_PATH)`
- **发现方式**：换源后逐项检查产物落在哪
- **教训**：**「参数看着生效、结果不对」是这类 bug 的典型表现**。
  顺带一条相关纪律：重设全局变量时**每个名字都要写进 `global` 声明**，
  漏一个就会出现同样的症状

#### 坑 11｜一键入口立刻抓出 2 个休眠 bug

这两个 bug 平时手工逐条跑**不会暴露**，因为都在「不联网的轮次」才走的代码路径上。

**(a) `extract.py` 的 `NameError`**

```python
f"停用词占比 {extra.get('stopword_ratio')}。"   # NameError: extra 未定义
```

`stopword_ratio` 实际存在 `res["extra"]` 里，而这段代码的作用域内没有 `extra` 变量。
**抽取步骤直接崩，管线断在第二步**。

**(b) `fetch.py` 的粘性缓存写 `None`**

```python
# ❌ 只看 status
if result["status"] == STATUS_OK:
    fetcher.save_to_archive(url, result["body"], ...)   # body 可能是 None
```

`fetch()` 的**粘性结论缓存**分支会返回 `status="fetched_ok"`（沿用上轮已取得的状态码）
**但 `body=None`**（本轮没下载内容）。于是把 `None` 写进文件 → `TypeError`。

- **修复**：`if result["status"] == STATUS_OK and result.get("body") is not None:`
  并写脚本复查全文再无「只看 status 就落盘」的写法
- **发现方式**：`run_all.py` 首次完整跑（第 ⑥ 步用 `--dry-run`）
- **教训**：**一键入口的价值不只是省事，它会把「只有特定路径才走到」的代码跑一遍**。
  这些路径手工测试时容易被跳过

### 4.4 我自己的失误（不放水）

以下都是我在本次过程中犯的错，一并记下。

| # | 失误 | 后果 | 教训 |
|---|---|---|---|
| 1 | 正则贪婪匹配 | 把 `retarget_artifacts` 函数**整个删掉** → `NameError` | 删除类正则该用**行号定位**，不用 `re.sub(..., flags=re.S)` |
| 2 | `re.sub` 替换串含 Windows 路径 | `\W` 被当成转义 → `re.error: bad escape \W` | 替换串含反斜杠时用 **lambda**：`re.sub(pat, lambda m, v=val: v, ...)` |
| 3 | 改常量区时误改默认值 | `SITE_HOSTNAME` 从 `themodernsoftware.dev` 改成别的 | 重构常量时**逐字核对原值**，别顺手「优化」 |
| 4 | USAGE 里打错课程名 | 写成 `CS1468S_offline`（正确是 `CS146S_offline`） | 文档里的标识符要**从源码复制**，不手打 |
| 5 | 核验脚本用整串相等 | 判断短数字 `"31"` 时误报自己去核验失败 | 短数字是子串，**核验逻辑本身也要验证** |
| 6 | 文档示例用 `\` 续行 | 示例**在 PowerShell / cmd 里跑不了**（`'--source-root' is not recognized`） | 跨平台可粘贴的命令**写成单行** |
| 7 | 复合命令链里 `Remove-Item` | 前一步失败时把待用文件也删了，得重建 | 清理动作**不要和依赖它的操作放同一条命令** |
| 8 | PowerShell heredoc | `python - <<'PY'` 在 PowerShell 里语法错误 | PowerShell 不支持 heredoc，**写成文件再执行** |
| 9 | `shlex.split` 解析 Windows 路径 | `ValueError: No escaped character` | 处理 Windows 路径用 `shlex.split(..., posix=False)` |
| 10 | `raise X if cond else None` | `TypeError: exceptions must derive from BaseException` | 这类条件表达式**不能用于 raise** |

> 这批失误有一条共同点：**都发生在「顺手做的小事」上**
> （改常量、写示例、清理文件、写一行验证）。
> 主线逻辑反而因为反复自测而没错 —— 这是个值得记住的规律。
